# T2、T3、T6、T7 完成后及时通知修复计划

## 已确认的目标与方案

用户在 2026-11-15 明确选择「改为完成后尽快通知」。主动订阅默认每分钟查阅一次历史，发现订阅后的完成轮次立即通知；60 分钟仅表示无活动超时，最长仍为 24 小时。任务执行与检查失败、通知投递分别记录。

实现选择：沿用 TypeScript、Node.js 内置定时器与现有订阅对账接口，以插件直接调用检查服务替代唤醒接收模型执行检查。相比每分钟唤醒模型，直接检查没有额外检查模型费用，也不会依赖模型是否调用工具。相比保持每小时检查，满足用户这次明确改变的通知时效要求。共用 macOS/Windows 实现，不修改 Codex 历史或接管桌面执行。

## 实施步骤

- [ ] 先补失败回归：未到超时也读取并识别完成、未完成不提前超时、重复防重、插件计时器不调用宿主创建提醒。
- [ ] 检查执行器分离检查周期与无活动超时；明确完成证据优先于活动游标变化；暂停、停止与硬到期仍生效。
- [ ] 增加插件调度器，保持原 Scheduler 接口、订阅持久化和启动对账；迁移旧 Relay 提醒，保留其他宿主任务；卸载等待在途检查并关闭计时器。
- [ ] 新订阅默认 60 秒检查，页面和工具说明同步。本次报告的接收会话已正确创建，不修改其他接收会话行为。
- [ ] 通过完整交付门禁，备份并升级本机日常实例，通过官方 RPC 将用户报告的原订阅设为 60 秒检查；确认原始基线对应的新完成轮次投递一次。
