# T2.6、T3.2、T3.3、T4、T6.3、T6.5：M4 主动通知与配置实施

日期：2026-11-11（Asia/Shanghai）。

## 已实现

- 共享通知凭证服务：只保存 SHA-256 摘要，生成和重置时一次返回明文，使用安全比较校验，凭证文件权限为 0600。
- push HTTP：监听 loopback，默认端口 37421，可由 `DSH_AGENT_RELAY_PORT` 调整；路径为 `/api/agent-relay/notifications`，使用 `Authorization: Bearer <token>`。
- push 请求校验结果枚举、摘要长度和外部引用；可省略 `subscription_id`，直接携带稳定 `request_id`、`agent` 和 `external_session_id`。首次请求按 `push:<request_id>` 创建一次性 push 订阅，重复请求复用该订阅并依赖订阅唯一标记幂等处理。
- 直接 push 或预注册 push 订阅缺少接收会话时，在 Agent Relay workspace 目录创建 DSH 会话并回填 `dsh_session_id`，再交给统一通知投递服务；直接 push 创建订阅不要求 Relay 重新读取外部会话快照。
- T3.3 使用 `skills/external-agent-notification/SKILL.md`，只描述外部 Agent 消息通知；通过 Agent 会话 ID、可选订阅 ID 和能力声明承载 Claude/Codex 差异。
- 订阅支持独立修改有效期、空闲时长和 poll 检查周期；检查周期改变时重建 schedule。
- 看板凭证抽屉接入生成、重置和摘要展示。

## Skill 复用结论

多个 Agent 可以共用一份通知 Skill。通知协议、认证、订阅状态和结果枚举都属于 Relay 合同；Agent 差异只影响如何取得外部会话 ID、如何判断任务结果，以及当前是否支持发送。Skill 不创建订阅、不调用 `relay_send`，直接 push 时由 Relay 按 `request_id` 创建一次性订阅，没有复制 Claude/Codex 两套流程。
