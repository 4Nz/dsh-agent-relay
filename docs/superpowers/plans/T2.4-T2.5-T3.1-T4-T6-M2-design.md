# T2.4、T2.5、T3.1、T4、T6：M2 主动订阅闭环设计草案

日期：2026-11-11。状态：用户已授权自主完成设计和实施。

## 目标与范围

让 DSH 用户从工具或看板创建 poll 订阅，由 DSH schedule 提醒唤醒模型调用 relay_check，到期检查后生成一次结果通知，持久投递到绑定的 DSH 会话，并在看板显示检查与投递状态。

包含 T2.4、T2.5、T3.1 订阅相关工具、T4 页面所需接口、T6.1、T6.2、T6.4，以及服务端入口接线和 T7.1、T7.2 验收。注册现有 Claude、Codex Adapter；Codex 保持只读。M2 页面仅创建 poll，不开放尚未完成的 push 入口。T2.6、T2.7、relay_send、外部 Skill 和新建通知会话归后续里程碑。

## 方案与约束

沿用 docs/tasks.md 和 T0 已确定的 schedule 提醒方案；不用插件定时器替代订阅检查。插件定时器仅驱动通知重试，不改变检查的触发方式。沿用 TypeScript、Cordis、node:sqlite，工具和页面共用服务。

另一个方案是插件直接定时检查，可消除模型调用工具的不确定性，但改变既定方案并脱离 DSH 定时任务管理，因此不采用。页面通信优先复用 DSH 现有认证连接，不额外开 HTTP 端口。

## 检查服务 T2.4

按 subscription_id 加锁；重复调用返回检查中。暂停、结束及未到期订阅直接跳过。手动立即检查也不提前结束尚未到期的订阅，其含义需在页面说明。

达到 hard_expires_at 时生成 expired；否则按订阅 cursor 调 Adapter.snapshot。关闭生成 session_closed；busy 或位置有更新时保存新检查位置并顺延有效期；无更新时按基线后的已结束轮次产生 completed、failed 或 idle_timeout。必须保留足以判断新轮次结果的基线，避免第一次观察新消息后丢失最终结果。

查询失败独立记录 last_check_status、last_check_error 与连续失败次数，顺延后重查；达到阈值生成 unreachable。成功清零连续失败次数。更新前重读订阅，防止异步 snapshot 期间用户停止或暂停后仍产生通知。通知与 poll 结束继续使用存储事务和唯一约束。

结束后删除对应提醒；失败保留以供对账重试。重复 relay_check 不得重复生成或发送通知。

## 通知服务 T2.5

投递 transport 与业务服务分开，支持测试替换。本机 DSH schedule 实现提供了依据：resolveAgent 返回结果后调用 resolved.agent.followup(message)，再调用 sessions.flush(resolved.agent.session)；flush 成功代表消息持久进入收件箱，不代表模型执行完成。

入口先取得数据目录独占 SQLite 执行锁，确保恢复发生在旧实例退出之后。通知使用稳定 delivery_key 关联 DSH 消息。发送前和未知结果恢复时核对会话记录；确认已有消息则 flush 并确认送达；确认没有且旧执行已退出才允许重试。核对失败保持 unknown。followup 后异常或 flush 未确认不得直接当成未发送。

最多三次投递尝试，明确失败使用退避重试；超过次数停止自动重试并在页面显示失败。重启先 recoverInterrupted，再核对 unknown，处理 pending 和到期 failed。增补存储枚举接口，避免只处理新通知。插件卸载先停止驱动并等待在途操作结束，再关闭数据库。

使用专用临时 DSH 会话验证持久化、消息标识核对及唤醒，不对业务会话发送测试通知。

## 入口和工具 T3.1

入口创建 Adapter 注册表、两个 Adapter、Scheduler、订阅服务、检查服务和通知服务，声明实际使用的 schedule、sessionController、sessions 等注入项。启动完成恢复和对账后开放操作，失败明确记录并允许恢复。

提供 relay_list_sessions、relay_subscribe、relay_list、relay_stop、relay_check，保留 relay_ping。工具调用从执行上下文获取当前 DSH 会话作为默认接收目标，不能用外部会话标题或 cwd 路由。输入在服务边界统一校验。订阅创建成功但提醒创建失败时，返回明确的待对账状态，不能声称定时检查已就绪。

## T4 与 T6 页面

提供 Agent 能力、候选外部会话、订阅分页列表和详情、创建、暂停、恢复、停止、检查接口，复用同一服务层。只暴露 M2 已实现操作。

看板显示 Agent、类型、外部标题与 ID、订阅状态、结束原因、有效期、最近检查及错误、通知投递状态。支持 Agent、类型、状态筛选和分页，显示加载及错误状态。提供暂停、恢复、停止、检查和打开接收会话。

新建订阅选择 Agent、外部会话、接收 DSH 会话及有效期。poll 必须绑定有效的 DSH 会话。Codex 仅展示已有只读能力，不出现可用的发送操作。页面复用 DSH 插件布局和主题。
