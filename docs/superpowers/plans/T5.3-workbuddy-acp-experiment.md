# T5.3 WorkBuddy ACP 实验发送开发与验收

日期：2026-11-18。继续使用 `codex/workbuddy-readonly` worktree。用户确认现有调研足够支撑开发测试；这不代表正式开启发送能力。

实施状态：实验客户端、Adapter 开关与回读验证器已实现，313 项自动化测试与安装包检查通过。专用 A/B 的一次真实请求返回 `-32603`，未确认投递；定位为端点项目与目标项目不匹配后，新增发送前项目校验。详见 [T5.3 ACP 验证记录](../../research/T5.3-workbuddy-acp-validation.md)。

## 本轮范围

1. 实现 connect、initialize、session/prompt 和有截止时间的 JSON-RPC/SSE 客户端。忽略 SSE 注释，按请求 ID 匹配响应，固定一次操作的端口和凭据，不做发送重试。
2. Adapter 仅通过显式实验配置、专用会话白名单和回读验证器启用发送；插件默认注册仍为只读，runPrompt 不开放。
3. conversationId 与工作会话 ID 的映射由测试方提供可核验的绑定解析器；不根据标题、当前 live、时间邻近或工作区猜测。发送前建立历史基线，发送后核对绑定未变及新增精确 user 消息。
4. 验证握手失败、writer_occupied、SSE 分片、只有 :ok、回执丢失、目标错配、绑定变更、凭据变化、权限请求和并发发送。
5. 更新测试结果和未验证边界，运行类型检查、全量单测和安装包检查。

## 状态约定

- 默认关闭、非白名单目标、端点项目不匹配、明确 writer_occupied：rejected。writer_occupied 仅识别协议错误中精确标记或结构化 code，不通过任意错误文本猜测。
- prompt 尚未尝试发送就失败：failed。
- prompt 已尝试发送但没有匹配的有效结果，或结果正常但目标回读未确认：unknown，不自动重发。
- 匹配的 prompt 结果含已知 stopReason，且发送后原绑定工作会话新增精确 user 消息：sent。sent 仅说明收件事实，不把 stopReason 推断为用户业务目标完成。
- 不从 SSE 注释、HTTP 200/202、session/update 文本或同工作区身份推断 queued/sent。

## 尚不实施

session/load 自动接管、Jobs 后台任务、生产环境开关、日志推测映射、服务端未知的断开 API，以及已有业务 SQLite 数据迁移均不属于这次实验发送实现。客户端关闭本地流不代表服务端连接/写锁已释放。

同会话并发锁和 unknown 阻断目前仅保存在 Adapter 实例内；重启恢复与跨实例防重尚未实现。不得通过重启实例绕过未知结果后重发。

## 真实补测

需要专用对话 A/B 和发送时有效的 A → 工作会话绑定证据。UI 停留 B 时给 A 发唯一标记，核验 A 的 user 记录及回复、B 无标记；随后验证繁忙、切换、工作会话回收与 App 重启。Windows 单独验收。没有这些条件时只运行合成数据与隔离 HTTP 服务，不接触业务会话。
