# T5.1 Claude Adapter

日期：2026-11-11。环境：macOS，Claude Code CLI 2.1.311，Node.js v24.14.0。依据：`docs/claude-session-relay-feasibility.md` 和本机会话记录的结构统计。

## 范围

实现 `AgentAdapter`（T2.1 接口，定义在 `src/adapters/types.ts`，已单独合入）的 Claude 版本：列出会话、取快照、发送消息。尚未接入插件入口、注册表（T2.2）和服务层，也没有提供工具。

| 文件 | 作用 |
| --- | --- |
| `src/adapters/types.ts` | `AgentAdapter` 接口、`Snapshot`、`SendResult`、`AdapterError` |
| `src/adapters/claude/index.ts` | `createClaudeAdapter(options)` |
| `src/adapters/claude/transcript.ts` | 解析会话 JSONL，判定轮次是否结束 |
| `src/adapters/claude/runner.ts` | 调用 `claude` CLI，不经过 shell，消息从 stdin 传入 |

## 数据来源

- 会话记录：在 `$CLAUDE_CONFIG_DIR/projects`（默认 `~/.claude/projects`）的各子目录下按 `<sessionId>.jsonl` 查找，不按 cwd 拼路径。
- 运行状态：`claude agents --json`。列表里只有被进程持有的会话：`status=busy` 为 `busy`，`status=idle` 为 `idle`（同时 `held=true`）。不在列表中表示无进程持有。后台会话只有 `state`（如 `blocked`），含义未验证，按 `unknown` 处理。
- 命令失败、超时或输出无法解析时，`runtime=unknown`，`runtime_error` 写明原因。

## 快照判定

- 找不到会话文件：`closed=true`，对应订阅的 `session_closed`。
- 读取失败、中间行无法解析：抛出 `AdapterError`，属于检查失败。最后一行可能正在写入，无法解析时跳过。
- `cursor` 为最后一条 user / assistant / system 记录的 `{uuid, timestamp}`，用作订阅基线。基线 `uuid` 找不到时按时间回退。
- `finished_turn` 只看基线之后的最近一轮，即最后一条用户提问之后的记录。提问不含 `isMeta` 注入消息和工具结果。
  - 最后一条为 assistant，且 `isApiErrorMessage=true`：`failed`。
  - 最后一条为 assistant，且 `stop_reason=end_turn`：`completed`。
  - 其余情况（`tool_use`、仍有工具结果待处理、之后又有新提问）：未结束。
  - 会话处于 `busy` 时一律视为未结束。
- `last_reply` 取最后一条 assistant 文本，截取前 1000 字。

本机近 40 个会话文件的统计结果：assistant 的 `stop_reason` 只出现过 `end_turn`、`tool_use`、`stop_sequence`。`stop_sequence` 全部带 `isApiErrorMessage=true`。标题来自 `ai-title` 记录的 `aiTitle`。

## 发送消息

1. 会话 ID 必须是 UUID，消息不能为空，否则抛出 `invalid_input`。
2. 找不到会话：`rejected`（会话不存在）。
3. 状态查询失败时 `rejected`。被进程持有（如开着的终端）的会话不启动进程：已配置 channel 时交给 channel 排队（返回 `queued`）或按其原因拒绝，见 `docs/superpowers/plans/T2.7-T5.1-T6.6-T7.4-claude-channel-relay.md`。无进程持有且 `busy` 时拒绝。
4. 执行 `claude -p --resume <id> --permission-prompts none --output-format json`，消息从 stdin 传入，cwd 使用会话记录中的 cwd。
5. 在发送前的基线之后，会话记录中出现内容相同的用户提问，即为 `sent`，`external_ref` 为该记录的 `uuid`。不等这一轮执行完，结果由后续快照获得。
6. 进程已退出但记录中没有该消息：`is_error=true` 或退出码非 0 时为 `failed`，其余为 `unknown`。
7. 等待写入超过 `acceptTimeoutMs`（默认 120 秒）：`unknown`，不重发。
8. 同一会话的发送在进程内串行执行。

不使用 `--dangerously-skip-permissions`；需要授权的操作会被自动拒绝。

## 验证

- `rtk npm test`：存储和 Adapter 单元测试共 22 个，全部通过。Adapter 测试使用临时目录和模拟的 CLI，覆盖记录解析、轮次判定、`closed`、`busy` 不判定结束、各类拒绝、`sent` / `failed` / `unknown` 以及串行发送。
- 真实冒烟测试：`test/smoke/claude-smoke.js` 在临时目录新建专用会话，依次验证快照、列表、发送、发送后轮次结束且回复包含埋入标识，以及不存在会话为 `closed`。会产生少量模型费用，不在 `npm test` 中运行。

2026-11-11 冒烟测试结果（Claude Code 2.1.311，测试会话 `5c0971c9-9b57-4170-88be-5aa63d052eb7`，cwd 为系统临时目录）：

| 步骤 | 结果 |
| --- | --- |
| `-p --session-id` 新建会话并埋入随机标识 | 成功 |
| 基线快照 | `closed=false`，`runtime=idle`，`held=false`，`finished_turn=completed`，cwd 与新建时一致 |
| `listSessions` | 找到该会话，`runtime=idle` |
| `sendMessage` 询问标识 | `sent`，返回写入记录的 `uuid` |
| 发送后按基线取快照 | 新一轮 `completed`，`held=false`，最后回复包含埋入标识 |
| 不存在的会话 ID | `closed=true` |

本次只验证了无进程持有时的正常路径；拒绝、失败和 `unknown` 路径由单元测试覆盖，未在真实会话上触发。

运行方式：

```bash
rtk npm run build
rtk proxy node test/smoke/claude-smoke.js
```

## 未验证与限制

- 后台会话（`kind=background`）的状态含义和发送方式。
- 被终端持有的会话不再用 `--resume` 注入（两个进程写同一会话），改由 channel 投递。
- 工具执行出错、用户中断（Esc）不会判为 `failed`，只按是否 `end_turn` 判定。
- `-p` 进程在消息写入后继续在后台执行，插件退出时不会等待它。DSH 重启后，该轮结果由下一次快照获得。
- JSONL 格式不是公开接口，Claude 版本变化可能导致解析失败，届时按检查失败处理。
