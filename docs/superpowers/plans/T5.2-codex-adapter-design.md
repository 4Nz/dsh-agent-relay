# T5.2 Codex Adapter 设计与实施

## 范围与方案

实现会话发现、只读快照与不支持发送的能力声明。连接已有 daemon 的 Unix WebSocket，不启动、恢复或接管外部会话，不读写 Codex 数据库。不使用桌面内部工具作为插件运行依赖。独立 stdio 实例也是历史查询的候选，但不能提高桌面实时状态可信度，因此沿用本机 daemon 路线。

使用 `src/adapters/types.ts` 的 AgentAdapter（创建 worktree 时 main 已合入 T2.1 与 T5.1）。时间统一为毫秒。`held` 在无法确认时保守返回 true；daemon 未加载会话时 runtime 为 unknown，不推断 idle。最近轮次 completed/failed 只表示轮次结果，且必须在基线之后开始；不表示用户整个目标已完成。

快照每次刷新最近轮次，游标包含轮次、状态、内容摘要与最近活动时间，避免同一轮结束后游标不变。基线之后未开始新轮次、历史为空、未知轮次状态均不报告完成。归档通过 archived 列表确认，查询失败不推断删除。历史回复只返回最多 1000 字符的节选，不保存无关正文。

## 验证重点

未知状态、错误响应和连接失败不得被转成 closed/completed；同一轮次在基线之后完成不当作新任务；最近轮次仍在执行时不回退旧结果；翻页游标重复必须报错；查询只允许 initialize、initialized、thread/list、thread/read、thread/turns/list。

依据：`docs/tasks.md`、`docs/codex-session-relay-feasibility.md`、本机 daemon 0.167.1 生成的 JSON Schema，以及 [App Server 官方文档](https://developers.openai.com/codex/app-server)。独立 Adapter 阶段未挂载；M2 已将现有 Adapter 注册到插件入口并提供只读工具和页面入口。

## 使用与对接

服务层内部导入 `src/adapters/codex/index.ts` 的 `createCodexAdapter(options)`，返回统一 `AgentAdapter`；构建后对应 `lib/adapters/codex/index.js`。默认连接 `$CODEX_HOME/app-server-control/app-server-control.sock`，未设置 CODEX_HOME 时使用 `~/.codex`。可指定 `socketPath`、`timeoutMs`（每次请求默认 15000 毫秒）或注入其他只读 `connect`。

`listSessions({ limit })` 默认最多 50 条，可设 1～1000，按更新时间倒序，排除归档；跨模型 provider、来源类型查询，按 ID 去重。`snapshot(id, baseline)` 每次获取最新一轮完整 items，返回最后回复节选；`sendMessage` 始终 rejected，且不建立连接。

2026-11-17 修订：正常实时状态 unknown 的能力说明放在 runtime_note，runtime_error/check_error 为 null；status_context 标明历史轮次状态与运行状态来源，不以 interrupted 断言桌面已中断。实际 RPC 失败仍抛出错误，供检查器累计失败。

基线为本 Adapter 产生的 `{ uuid, timestamp }`，服务层负责序列化到存储 cursor。uuid 为 `codex:<轮次ID>:<状态和内容摘要>`，timestamp 为毫秒。最近轮次必须与基线轮次不同，且开始时间晚于基线，才可报告 finished_turn；缺少开始时间时保守返回 null。同一轮在基线之后完成会改变游标，但不视为基线之后新开始的任务。

归档列表每次完整查询，最多 1000 页，每页 100 条；遇到重复游标、超限或查询失败时报错。对 `thread not loaded` 等明确候选错误，还须在完整活动列表中确认 ID 不存在才返回 closed，避免把 daemon 未加载直接视为删除。该方式优先保证正确性，会话很多时查询成本较高，尚未引入缓存或归档事件订阅。

传输仅允许 `thread/list`、`thread/read`、`thread/turns/list`，初始化使用 initialize/initialized。支持分段、连续分片、ping/pong；响应消息上限 16 MiB，超时、断线和解析失败均结束连接并拒绝待处理请求。每个 Adapter 操作独立连接，失败后下次操作重新连接。
