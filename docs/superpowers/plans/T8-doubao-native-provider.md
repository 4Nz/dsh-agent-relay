# T8 豆包内置 Provider 实施与验证

## 已确认范围

按用户要求，由本插件实现豆包登录和 HTTP/SSE 调用，不依赖 `dsh-connect-doubao`，也不读取连接器凭证。保留 Provider 端口，现有订阅、桥梁、Push 和 Claude/Codex Adapter 不参与豆包任务执行。

实现分为凭据与登录模块、HTTP 传输模块、设置页与宿主接线。运行时只使用 Node.js 内置模块。协议参考 2026-11-19 调研及本机安装的 0.7.2 连接器源码；研究中的 0.7.3 实测不能等同于本实现已经验收。

## 实施项

1. 私有目录保存 Cookie，原子替换，目录权限 0700、文件 0600；普通 TeamRelay 配置和页面不含 Cookie。使用权限隔离的明文文件，不宣称系统钥匙串加密。凭证损坏明确失败，退出后旧响应不能重新写回凭证。
2. 用户点击登录才启动专用 Chrome/Edge，使用独立临时 profile、随机调试端口、回环 CDP。用户自行扫码或短信登录，只收集适用于豆包站点的 Cookie。支持取消、超时与宿主停止清理；关闭设置页保留服务端登录任务。
3. 固定 HTTPS `/chat/completion`，普通对话、快速模型 `0`、关闭思考，无工具定义。不跟随携带 Cookie 的重定向，不自动重试。SSE 完成标记前断流或发送后超时标记结果未知；只拼接回答，不返回思考与用户回显。
4. 账号探测不生成回答。区分未登录、等待登录、登录态已保存、检测有效、失效、暂不可用。网络异常不能等同于凭证失效。有效状态不是模型真实执行验收。
5. 注册豆包 Provider；设置页提供登录、检测、取消、退出。可先分配类型再登录。四个默认类型仍全部使用 DSH，WorkBuddy 暂不支持。
6. 使用模拟 HTTP/SSE、模拟登录和临时凭据文件验证错误、超时、竞争与保密边界；设置页验证保存与交互，最后运行完整 `release:prepare`。

## 验收边界

本轮不会读取业务登录态，不自动操作验证码，不执行真实付费模型冒烟。完整 TeamRelay 自动调度器仍属于后续任务；接通 Provider 并不代表模式入口和自动派发链路已完成。真实浏览器认证及豆包请求须在用户完成登录后另行验收。
