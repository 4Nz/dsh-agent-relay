## 目标与设计

支持 DSH 向 Relay 创建并登记的本机 Codex daemon 会话发送消息，保留上下文、消息状态和一次性完成通知。桌面原实例及未登记会话继续只读；不实现 steer、排队或自动审批。复用现有 daemon，不自动重启或升级用户的 Codex。

已有实测：2026-11-12，daemon 0.167.2，经 Unix socket 创建专用会话，发送 FIRST_OK 后断开重连，恢复同一会话并正确取回上一轮口令。该探测不是 DSH 宿主验收，也未验证工具执行和审批。

方案比较：桌面桥接缺少已验证外部入口；任意历史会话直接 resume 无法确认原执行实例；因此采用 Relay 创建会话并持久登记端点的受限方案。绑定仅证明 Relay 的创建来源，不构成跨桌面/CLI 的全局排他锁；这些会话应专用于 Relay，不能同时交给其他执行实例。写入前仍核对同一 daemon 的实际状态。

## 全局约束

- Node.js >=24，TypeScript ESM，仅 Node.js 内置模块和现有 DSH 包。
- 主目录保持 main，全部修改位于独立 worktree，文档及提交说明使用中文。
- 原权限策略不提升；审批明确拒绝，不以普通文本冒充授权。
- sent 仅表示已接收；写入后的超时/断线为 unknown，不自动重发。
- 已有订阅游标兼容；发送后订阅按实际 turnId 跟踪，包含空历史、同秒结束及后续轮次覆盖场景。

## 文件与接口

- storage/codex-sessions.ts、schema.ts、index.ts：追加迁移；登记 session_id、endpoint、created_at，仅 Relay 创建成功后登记。
- adapters/types.ts：可选 createSession 能力/方法，会话级 send_allowed/send_reason；订阅目标轮次字段。
- adapters/codex/rpc.ts：读写模式分离，结构化传输错误，通知回调和正确审批拒绝。
- adapters/codex/index.ts：创建、登记、受限发送、持久写连接、关闭连接；未绑定会话保持原只读行为。
- services/relay.ts、subscriptions.ts、checks.ts：新建会话入口、目标互斥及精确轮次订阅。
- index.ts、tools.ts、client.ts：服务接入、工具与页面创建入口、按会话显示发送资格。
- test：临时 SQLite、Unix socket 协议测试、Adapter 和服务回归、真实专用会话冒烟。

## 审查重点

1. 端点不匹配和未绑定会话必须拒绝，不能通过客户端伪造资格。
2. turn/start 发出后响应丢失不能归类为明确失败。
3. 收到审批请求须正确拒绝，保持原权限策略。
4. 插件停止、连接丢失和同目标并发不能重复执行。
5. 目标轮次结束后即使出现后续轮次，也不能通知错轮次。
