## 目标与范围

让 DSH 用户通过 `relay_send` 工具或页面入口向外部会话转发一条消息，记录转发结果（sent / rejected / failed / unknown），并可选择“发送后订阅”在发送成功后自动创建一条 poll 订阅；同时补齐 T4 的修改检查周期与有效期接口，并推进 T6.3 通知会话分组。

包含 T2.7 转发服务、`relay_send` 工具、转发记录查询接口、T4 的 `PATCH /subscriptions/:id`、T6.3 分组前置收尾，以及 T7.4 转发验收。不包含 T2.6 外部通知入口、push 订阅、外部 Agent 侧 Skill；Codex 保持只读，发送声明为不支持。

## 转发服务 T2.7

新建 `src/services/forward.ts`，暴露 `send` 与 `list`，与工具、RPC 共用。

### 发送流程

1. 校验 `agent`、`external_session_id`、`content`（非空、长度上限）。
2. 取 Adapter，检查 `capabilities().sendMessage`：不支持（Codex）直接记录 `rejected` 并返回，不调用 Adapter。
3. `store.messages.create({ status: "sending", ... })` 先落库。
4. 调用 `adapter.sendMessage(external_session_id, content)`。
5. 按返回 `SendResult` 调 `store.messages.transition()` 落到 `sent`/`rejected`/`failed`/`unknown`；`sent` 记录 `external_ref` 与 `sent_at`，`rejected`/`failed`/`unknown` 记录 `error`。
6. 发送成功后调 `subscriptions.touch(agent, external_session_id)`，顺延该外部会话所有未结束订阅的有效期（发送即用户活动）。
7. 若请求了“发送后订阅”且结果为 `sent`，复用 `subscriptions.subscribe()` 创建一条 poll 订阅；接收会话默认当前 DSH 会话。

### 结果与状态

复用 `MessageStatus`。工具与页面把“已发送”与“已完成”区分展示：`sent` 只表示消息已进入外部会话记录，任务是否完成由订阅检查得出。`rejected` 必须带原因（处理中 / 终端持有 / 不支持）。`unknown` 不盲目重发。

### 发送后订阅

发送成功即按“有效期”一节规则创建 poll 订阅，行为与 `relay_subscribe` 一致：默认有效期 1 小时、最长 24 小时，绑定调用工具的 DSH 会话为通知目标。发送失败或 rejected 不创建订阅。

## relay_send 工具与 RPC（T3.1 / T4）

- 工具 `relay_send`：参数 `agent`、`external_session_id`、`content`、`subscribe_after?`。发送前由模型复述目标会话（写入工具描述，配合 T3.2 Skill）；返回消息记录与订阅创建结果。
- 工具 `relay_messages`：分页查看转发记录（按 agent / external_session_id / subscription_id 过滤），供核对“已发送”与结果。
- RPC 新增 `send_message`、`messages` 两个端点，挂在现有 `/api/agent-relay/<操作>`，复用同一服务层；不新开 HTTP 端口。
- `relay.ts` 的 `subscribe` 分支目前仅开放 poll，`relay_send` 走新的 `send_message` 端点，不扩大 `subscribe` 的对外类型范围（发送后订阅在服务层内部直接创建 poll）。

## T4 PATCH 修改周期与有效期

- RPC 新增 `update` 端点：`PATCH /subscriptions/:id` 语义，可改 `check_interval_seconds`、`idle_timeout_seconds`（范围 60～86400 秒），复用 `store.subscriptions.update()`。
- 改 `check_interval_seconds` 时重建 schedule 提醒（`everySeconds` 变化），失败保留旧值并返回明确错误，不静默丢失定时任务；改 `idle_timeout_seconds` 只影响后续顺延计算。
- 不允许改 `max_lifetime_seconds`、`hard_expires_at`（存储已禁止，接口同样拒绝并说明）。
- 前端看板补充周期/有效期修改入口（T6.2 新建订阅旁），未到期检查仍遵守截止时间。
