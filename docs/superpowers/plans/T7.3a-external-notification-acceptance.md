# T7.3a 外部 Agent 通知后的 DSH 用户消息提醒验收

状态：待真实浏览器验收。本清单于 2026-11-12 纳入 T7；不能以通知 RPC 单元测试或 DSH inbox 投递冒烟代替浏览器实际提醒。

## 验收目标与现有实现

外部 Claude / Codex 通过通知入口发送结果后，DSH 接收会话内有消息，并且用户可看到 Agent Relay 浏览器通知。会话消息投递与浏览器弹窗分别记录结果：弹窗出现不证明 DSH 会话已经送达，`delivered` 也不证明浏览器已弹窗或 DSH 后续处理完成。

当前实现为 `src/client.ts` 的浏览器 Notification 渠道：侧边栏图标挂载期间经 `notify_poll` 每 30 秒查询新增通知，本地保存游标；首次查询仅校准历史，正常新增通知标题为「Agent Relay 通知」，正文显示结果和摘要节选。前端关闭或图标未挂载时没有该浏览器轮询；macOS 独立原生通知和飞书等其他渠道不属于当前实现。本入口同时返回 poll 和 push 通知，本项重点覆盖外部 Agent push 链路。

## 环境与准备

- 使用隔离 DSH profile、专用 Claude/Codex 会话与接收会话；不清理或修改业务浏览器配置及业务会话。
- 记录日期、DSH/插件/外部 Agent 版本、浏览器与操作系统版本、通知权限、系统通知设置，以及前端处于前台还是后台。
- 安装待验收构建并加载 DSH 前端，确认侧边栏 Relay 图标已挂载、通知接口可访问。
- 首次授权场景由验收人员在真实浏览器完成，核对系统是否允许该浏览器显示通知；拒绝权限场景使用独立测试站点权限配置。
- 用稳定 `request_id` 关联外部请求、订阅、DSH 消息和用户提醒；凭证不写入截图、日志或验收记录。

## 场景与通过标准

| 用例 | 操作 | 通过标准 |
| --- | --- | --- |
| T7.3a-1 正常新增提醒 | 通知权限已允许，先完成首次轮询；分别由专用 Claude 和 Codex 发送全新的 push 通知。保持 DSH 前台正常轮询。 | 对应 DSH 会话各出现一条结果消息、push 订阅结束；新增通知在下一次正常 30 秒轮询周期显示，标题、结果和摘要与目标匹配；记录实际提醒延迟。 |
| T7.3a-2 无历史时的首条通知 | 使用没有历史通知及本地游标的隔离 profile，打开 DSH 并确认一次空轮询后，再发第一条 push。 | 第一条在打开页面后产生的新通知仍应提醒，不能被当作初始化历史吞掉；会话消息与弹窗分别核验。 |
| T7.3a-3 历史校准与刷新防重 | 准备若干打开页面前已存在的历史通知，使用新的测试浏览器存储首次打开；校准后再发一条新通知，收到后刷新页面。 | 历史不会集中补弹；新的通知正常显示；刷新后不重复提醒已处理通知。 |
| T7.3a-4 重复请求与连续新通知 | 对同一个 `request_id` 重复 push，并跨多个轮询周期观察；再使用不同 `request_id` 连续发送数条新通知。 | 重复请求不新增 DSH 消息或浏览器提醒；不同新通知均可关联各自结果，不串会话、不漏掉第一条。 |
| T7.3a-5 不打开看板与后台窗口 | 保持 DSH 应用和侧边栏挂载，关闭 Relay 看板或切到其他 DSH 会话；再切换浏览器标签页/窗口至后台并发送新通知。 | 无需打开 Relay 看板即可提醒；后台场景记录浏览器限速和系统通知限制、实际延迟，分别判断前端提醒与后端投递，不能把浏览器限速误记为服务端投递失败。 |
| T7.3a-6 权限拒绝或渠道不支持 | 在专用测试环境拒绝通知权限，另在不支持 Notification 的环境发送 push。 | 会话消息正常送达，订阅仍可结束；不反复索要已拒绝的权限，不因弹窗失败阻断消息投递或导致前端异常。 |
| T7.3a-7 查询失败与恢复 | 在已完成初始化的测试前端暂时断网或使通知查询失败，其间外部 Agent 成功 push；恢复前端连接。另发送一次认证失败的通知请求。 | 恢复后在下一次成功轮询显示断线期间新增的提醒，且不重复；认证失败请求不能生成有效结果提醒。后端发送结果、DSH 投递结果、轮询错误和浏览器提醒分别记录。 |

在前台基线通过后，可补测首次历史超过 50 条、同一时间戳多条记录、多个页面同时打开和持久存储不可用，核验分页、游标和提醒防重边界；遇到漏提醒或重复提醒登记缺陷，不降低通过标准。

## 重点风险与已有验证的界限

当前首次校准仅在查询返回了通知时写入游标；若第一次为空，随后首条新增通知可能仍进入首次校准分支。T7.3a-2 必须真实验证，不能用「接口返回成功」或「会话里有消息」替代弹窗结果；若失败按缺陷登记并修复。

现有 Codex 发送专项已验证 DSH inbox 唯一消息和后端投递，但没有验证本项的真实浏览器权限、弹窗、后台行为、刷新游标或跨标签页表现。当前 T7.3a 全部用例保持待验收状态。
