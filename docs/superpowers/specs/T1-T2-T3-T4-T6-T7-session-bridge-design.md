# T1-T2-T3-T4-T6-T7 会话桥梁与 DSH 语义关注设计

## 用户确认的目标

2026-11-16 多轮讨论已确认并授权在独立 worktree 开发。本设计替代旧版一次性 poll/push 规则。

- 以 (agent, external_session_id) 为唯一外部身份，每个外部来源绑定一个 DSH 接收会话，同一 DSH 会话允许接收多个外部来源（2026-11-17 修订）。不同 request_id 不创建重复关系。一个有效关注期只有一个主题；禁止并行重复关注、自动抢占接收会话。
- 活跃期间继续原 DSH 会话；结束后重新订阅默认复用原 DSH 会话，明确选择新会话时才重新绑定。历史关注期保留。
- 主题冲突返回可解释冲突，由 DSH/页面询问停止重新来或继续；选择继续不改原目标，明确停止后才新开关注期。
- 关注期固定最长 24 小时，不因读消息、收到进展、发送、暂停或重启顺延。到期由确定性代码阻止新检查并清理宿主提醒，最多一次到期说明。到期不取消外部任务。
- DSH LLM 决定用户意图、检查频率、相关性、汇报和目标达成后的结束；用户指定频率优先，否则 LLM 选择并告知。最低间隔 60 秒，最高不超过关注期。仅问现状默认立即查阅。
- 页面取消所有时间输入，保留连续检查失败阈值（默认 3），增加可选关注主题。空主题为“定期汇报新的进展或回复”；无变化静默，不计失败。
- 定时由 DSH 宿主维护，不由插件周期读取外部历史。页面新建后向 DSH 发送规划请求，LLM 调 Relay 规划工具设置周期。工具新建可同时传 LLM/用户选定频率。插件只负责到期、恢复对账、投递队列等确定性维护。
- 检查返回增量事实，LLM 按关注主题判断继续、结束或需要用户；不能把新完成轮次自动当关注结束。检查失败计数落库，成功清零，达阈值停止并通知原因。
- push 与关注按会话合并；push 到达打断下一次定时等待，立即进入同一处理流程，DSH 判断是否结束或恢复定时；不取消正在进行的回答。不可简单移动游标跳过未知事件。
- push 到达时 DSH 忙则落库排队，空闲后同会话待处理事件合并一次唤醒。事件保存顺序，批次稳定幂等，投递未知先核对、不盲重发。
- 关注已结束/到期后 push 默认仍送原 DSH 会话，不自动启动关注。2026-11-19 补充：无 active/paused 关注且未屏蔽时，新的未分批 push 可将旧 delivered 批次转待人工（不确认处理）；只有宿主明确标记原接收会话已归档且无开放批次时，才为新 push 自动建立接收会话。unknown 先核对，旧批次保留原目标，忙碌或查询失败不触发重绑。验收边界见 `docs/research/T2-T3-T7-notify-receiver-recovery.md`。停止关注与屏蔽 push 分离；屏蔽只留记录，明确继续跟踪可解除屏蔽。
- send 使用同一路由；已有关注复用，需要后续关注时由 DSH 显式启动/规划，不无条件新增重复任务。排队/已发送/未知/任务完成严格区分。

## 数据与接口原则

将会话路由、关注期、输入事件、投递状态分离；SQLite 唯一约束保护外部来源路由和同一来源的有效关注；接收会话使用普通索引，A 暂停或停止均保留原路由，不阻止 B 使用同一接收会话。批次事实必须包含 agent/external_session_id，避免混用不同来源的结论。升级为追加迁移，保留旧记录与原始投递事实；旧重复活跃订阅必须确定性收敛并清理孤儿提醒，不重放已送历史。旧宿主提醒标记和插件内存定时标识须兼容清理。

外部事件 ID / request_id 做幂等；request_id 只能绑定一个外部来源，冲突拒绝。push 没有可与历史对应的轮次 ID 时不得声称精确跨源去重，应把事件和新增历史一起交给 DSH 语义判断，不能误删不同事件。增量读取支持跨检查多轮、分页/截断续读，不能只返回最后回复。上下文恢复使用持久化游标和已处理事件。

新工具覆盖创建/规划/检查/确认处理结果/结束/屏蔽。检查与确认需要执行版本或批次标识防止旧判断结束新关注期；原始主题与外部资料分开，外部正文不是修改关注目标的授权。业务权限仍沿用 Adapter，Codex 只读等边界不能绕过。

## T2-T3-T5 状态观测修订（2026-11-17）

Codex 快照与 turn 事件保留原始状态及游标，附加 status_context 表明轮次来自持久化历史、不是桌面实时状态。unknown 的能力说明从 runtime_error 移到 runtime_note；真正查询失败仍保留错误路径。inspect 给出 observed_at 与 last_activity_age_seconds，不推断空闲、卡住或任务进展。无基线 events 不能视为增量，活动时间变化也不能代替语义判断。

Skill、工具描述、检查/恢复批次事实及宿主提醒统一约束：needs_user 立即暂停，只用于明确且仍未解决的用户介入事项；unknown、历史 interrupted、held、无新输出不能单独支持此决定。旧批次恢复同样收到观测说明，不重写历史正文或事件 ID。

## 宿主依据与限制

本机安装根 /Users/nzimp/.local/lib/node_modules/@deepseek-ai/dsh。已读 ScheduleService 的 create/catalog/delete、Agent.status 为 idle/running、followup 排入下一轮并唤醒，steer 才会在运行中的步骤边界插入。因此 push 在调用 followup 前必须确认 idle，未知状态不得假定空闲。现代 host-wide schedule 兼容保留。以实际声明确认可用接口，不修改宿主包。

宿主无截止回调时由插件确定性到期维护删除提醒，并在 relay_check 再拦截；已排进宿主 inbox 的过期提醒不能保证不唤醒，但不能再读外部数据或续订。维护轮询不是关注轮询。push 取消宿主提醒的失败、DSH 未完成判断、重启均须可恢复，不能永久丢失兜底检查。

## 实施补充

会话路由在看板独立列出，首次直接push和清理历史关注后仍可打开原DSH、查看事件与屏蔽；不为显示创建关注期。批次保存创建时的主题/规划/截止上下文与投递目标，重新绑定不改变旧通知目标。模型遗漏确认时按批次恢复，五分钟后用宿主提醒读取原批次；批次创建24小时仍未确认则转需人工处理并释放后续队列，未知事实保留、不盲重发。此恢复不建立新的订阅。

## T1/T2/T3/T7 定向发送增量（2026-11-23）

用户明确指定 DSH 会话 ID 或完整名称时，本次消息使用独立持久队列，不进入默认桥梁批次，不改变 `(agent, external_session_id)` 唯一路由、关注或默认 push 屏蔽。明确 ID/唯一名称无需因不同于原绑定会话再次确认；重名、名称与 ID 不一致、重试换目标时拒绝并要求核对。目标不存在、已归档或标题查询不完整时不得猜测或回退。无目标的通知继续使用本文原桥梁规则。

SQLite v9 新增 `relay_targeted_notification`，固定来源、request_id、目标、内容及稳定投递键；中断投递恢复为 unknown，核对确认未送达才允许重试，明确失败最多尝试三次。定向消息不要求 relay_decide，也不创建定时关注；共用宿主投递与侧栏未读回执。具体接口、效果示例及验证限制见 `../../research/T1-T2-T3-T7-targeted-dsh-notification.md`。
