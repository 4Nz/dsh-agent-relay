## T2.2 注册表

`createAdapterRegistry(adapters)` 按 `agent` 字段建表。重复注册会抛错；`get` 查不到时抛 `AdapterError("invalid_input")`；`list()` 返回各 Agent 及其能力声明，供 `GET /agents` 和页面使用。

## T2.3 订阅服务

`createSubscriptionService({store, adapters, scheduler, now, newId})` 提供以下方法：

- `subscribe(input)`：
  1. Adapter 不支持快照时返回 `unsupported`；`poll` 未指定 DSH 会话时返回 `invalid_input`。
  2. 先取一次快照。会话已关闭返回 `session_closed`，不建订阅。
  3. 以快照的 `cursor`、`last_activity_at`、标题和 cwd 写入订阅，有效期按存储层默认值计算（1 小时，最长 24 小时）。
  4. 再调用定时服务建周期提醒，周期默认等于有效期。建提醒失败时订阅保留，由对账补建。
  5. `push` 订阅未绑定 DSH 会话时不建提醒，绑定会话的时机属于 T2.5。
- `pause(id)` / `resume(id)`：按当前状态做条件更新，状态不符返回 `conflict`。恢复时从当前时间顺延有效期。暂停期间定时任务保留，由检查执行器（T2.4）跳过。
- `stop(id)`：结束为 `user_stopped`，然后删除定时任务。删除失败不影响结束，留给对账。
- `inspect(agent, sessionId)`：通过 Relay 查阅会话。会话存在时顺延该会话所有订阅；会话已关闭时调用 `closeSession`。
- `touch(agent, sessionId)`：发送消息后由转发服务（T2.7）调用，顺延有效期。
- `closeSession(agent, sessionId)`：为该会话每条未结束订阅登记 `session_closed` 通知。`poll` 随登记结束并删除定时任务；`push` 保持 `active`，送达后结束（存储层既有规则）。重复调用不产生第二条通知。
- `reconcile()`：启动时对账。为缺少有效定时任务的未结束订阅补建；删除提醒正文带本插件标记、但没有对应订阅的定时任务。不带标记的定时任务（用户或其他插件的）不处理。

### 定时任务

`Scheduler` 接口只包含 `create`、`delete`、`catalog` 三个方法。`createDshScheduler(ctx.schedule)` 把它映射到 `ScheduleService`：

| 订阅服务 | `ScheduleService` |
| --- | --- |
| `create({sessionId, title, prompt, everySeconds})` | `create(sessionId, {title, prompt, every_seconds})`，返回记录的 `id` |
| `delete({sessionId, id})` | `delete({sessionId, id})`，返回 `deleted` |
| `catalog()` | `catalog()`，取 `id`、`sessionId`、`prompt`、`status` |

提醒正文以 `[agent-relay:<订阅ID>]` 开头，要求 agent 调用 `relay_check` 工具，对账靠这个标记识别本插件的任务。标题最长 120 字（`MAX_TITLE_LENGTH`），超出部分截断。`every_seconds` 最小 60，存储层已保证 `check_interval_seconds >= 60`。

## T2.8 历史清理

`startHistoryCleanup({store})` 启动时清理一次，之后每 24 小时清理一次，返回停止函数。插件入口用 `ctx.effect` 注册，插件卸载时停止。清理按存储层规则删除满 30 天的通知和消息，不删除订阅。出错时记录警告，下次照常执行。

没有用 DSH 定时任务做清理：清理不需要模型参与，进程内定时器足够，而且清理本身幂等，重启后重新计时不影响结果。

## 未验证与限制

- 没有在真实 DSH 中调用 `ctx.schedule`。映射依据是类型定义，`create` 绑定会话和提醒到点投递的实际行为待接入后验证。
- 订阅服务尚未接入插件入口：入口需要 `inject` 增加 `schedule`，并在启动时调用 `reconcile()`。这一步和 T3 工具一起做。
- 定时任务建好后才写回 `schedule_task_id`，两步不在同一事务。进程在两步之间退出时，会留下一个没有记录 ID 的任务。对账会按标记把它当孤儿删除，再为订阅补建一个新任务。
- 检查周期等于有效期时，每条 `poll` 订阅每小时唤醒一次 DSH 会话。到期判定、顺延和结束属于 T2.4，本次未实现。
