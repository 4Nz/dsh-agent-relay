# T5.3 WorkBuddy ACP 实验发送实测与验收边界

验证日期：2026-11-18（Asia/Shanghai）。环境：macOS、WorkBuddy 5.11.3、Node.js v24.14.0、Relay 0.1.9；工作分支 `codex/workbuddy-readonly`。本文只记录脱敏诊断与结果，不包含 token、会话正文或完整历史。

## 结论

现有证据足以开发实验客户端及隔离测试，但尚不足以开放正式发送。默认 `sendMessage=false`、`runPrompt=false`；只有直接构造 Adapter 时显式提供实验配置、专用会话白名单和绑定验证器，才声明实验发送能力。插件默认注册不传入此配置。

一次真实请求完成 connect 和 initialize，随后 session/prompt 返回 `-32603`。测试窗口内 A/B 项目的 JSONL 均未发现唯一标记。结果保留为 `unknown`，没有重发，不能宣布送达，也不能仅据短窗口未见标记就保证没有任何副作用。

## 实现与状态语义

- `src/adapters/workbuddy/acp.ts`：connect → initialize → session/prompt；按 JSON-RPC ID 匹配结果，解析分片 SSE/JSON，忽略心跳注释。固定端口、PID 与凭据，prompt 前再次核对；401 请求刷新，操作内不重试发送。超时和响应大小有上限，诊断仅输出阶段与错误码。
- 发送前校验：白名单、同会话并发锁、先前 unknown 阻断、目标元数据、回读基线，以及 interactive 注册表中的端口/PID/cwd 与目标项目一致。不把会话列表可见、当前 live 或同工作区当作会话绑定证明。
- `src/adapters/workbuddy/delivery.ts`：由测试方提供可信 conversationId → workerSessionId/projectKey/generation 解析器。回读必须绑定不变、文件身份不变、历史前缀不变，且新增恰好一条精确匹配的 user 记录；旧记录、assistant 回复和重复同文均不能确认。
- 有效 prompt 结果仅记内部 `responded`；同时取得目标新增记录证据才返回 `sent`。发送前失败为 `failed`，明确拒绝为 `rejected`，发送后异常或回读未确认均为 `unknown`。`sent` 不表示业务任务完成。
- 不启用文件、终端或权限能力；拒绝相应服务端请求。不调用 session/load、Jobs，不回退给当前 live，也不直接写 WorkBuddy 历史。

同会话锁及 unknown 阻断目前只在单个 Adapter 实例内生效，尚无跨实例/重启恢复保证。生产绑定解析器及安全释放服务端连接/写锁的生命周期尚未验证。

## 真实 A/B 步骤与结果

用户提供专用 A 为目标、B 为只读对照。16:50 左右执行一次真实 prompt；未对 B 发消息。

1. 原 token 元数据所指端口拒绝连接。读取 interactive 注册表，找到另一个可用端点；使用现有凭据 health 返回 200，没有改写 token 文件。
2. 该端点会话列表包含 A/B；live 的 sessionId 为 null、writerOccupied 为 false，status 的 busy 为 false。这只说明该端点的观测状态，不能证明 A 空闲或完成。
3. 读取 A/B 测试项目文件建立标记不存在的基线，然后向 A 发起一次仅要求回复唯一测试标记的请求。
4. connect、initialize 成功；prompt 开始后返回 `-32603`。只读轮询约四秒，A/B 均无标记，工作会话映射未确认。
5. 脱敏核查对应端点日志发现 ENOENT：服务端在 CLI host 自身项目目录查找 A 的 JSONL，而 A 属于另一个项目。列表跨项目可见，并不意味着 ACP 支持跨项目路由。
6. 依据这一失败补上端点项目校验。新增隔离用例证明不匹配时在 connect/prompt 前拒绝；没有为了验证修复而再次真实发送。

未核验当时 UI 确实停留 B，因此本次也不构成“UI 停留 B 时精确发送 A”的成功验收。

## 自动化与复现

`rtk npm run release:prepare` 已通过：类型检查、313 项测试（0 失败、0 跳过）、干净构建、包清单检查和隔离 tarball 安装冒烟。产物位于 `dist/0.1.9/`，没有安装到真实 DSH 或发布。包清单检查另外修复了 npm 自动包含 `README.en.md` 的精确白名单；其他非允许 README 文件仍被拒绝。

专用诊断脚本为 `test/smoke/workbuddy-acp-smoke.js`，使用环境变量 `WORKBUDDY_TEST_A`、`WORKBUDDY_TEST_B`，可用 `WORKBUDDY_TEST_PORT` 选择已登记端点。脚本一次最多发起一个 prompt，不自动重试；当前缺少权威映射确认，诊断结束返回非零，不能拿退出码当作成功验收。新增项目门禁后，当前错配端点会在发送前被拒绝。

补测应先核对本次未知结果，再准备 A 项目的有效注册端点及可信工作会话绑定，确认 UI 停留 B。采用新的唯一标记独立测试，验证 A 的新增 user 记录和回复、B 无标记；不得通过重跑脚本或重启 Adapter 盲目重发原操作。

## 与默认只读接入的关系

会话发现、live/busy、history/replay 404 → 本地 JSONL 回退的既有验证见 [只读记录](T5.3-workbuddy-adapter-validation.md)。通知 Skill 真实安装回传、已有数据库迁移及完整 T7 宿主验收仍未完成，本次实验没有补齐这些边界。

另外，默认只读实现仍有待修正的状态/时间表达：非 live 会话目前可能被标为 idle，历史接口缺失时间时会合成时间。这些行为不能作为实时空闲、完成或新活动的证据；本轮 313 项通过也不代表整个 WorkBuddy 接入已具备上线条件。
