# T3.4-T6.6-T7.6 指定目录与可见会话接力验收

验证日期：2026-11-19～20；系统：macOS；Node.js 24.14.0；Claude Code 2.1.311；Codex CLI 0.163.0。使用用户授权的专用测试会话，测试消息只要求回复标记，不修改业务项目文件。本文记录独立 HTTP 测试服务与真实 Agent 的结果，不代表运行中的 DSH 宿主已升级。

## 行为与边界

提供有效会话 ID 时直接按 ID 发送，不要求重新选择目录；完整会话名称可精确查找，重名/查找截断由用户确认真实 ID。名称查找不直接发送、不创建会话。

没有目标会话时，先确定工作目录。绝对/相对路径必须真实存在且为可访问目录；项目名通过 Spotlight（macOS 已索引目录）与用户目录递归查找，可用 `--root` 补查其他磁盘。无目录、找不到、多个候选、搜索不完整时继续询问，目录确定前不创建、不默用当前目录或新建空目录。真实 `ai-rag` 项目名查找返回一个候选，随后与 Codex 已保存项目的真实路径匹配。

Claude 使用新 Terminal 窗口中的交互式 CLI，保留信任/channel/工具审批。Codex 使用桌面原生创建工具选择相同路径的 local 项目。当前 Claude CLI 没有该桌面创建工具：官方 `codex app <路径>` 只能打开新会话界面，仍需用户提交首条消息并提供 ID；不能宣称这条路径已实现全自动新建和发送。

接力 HTTP 只允许可见会话：Claude 发送时再次核对终端持有状态，退出后不回退到 `-p --resume`；Codex 拒绝 Relay 专用后台绑定，已有桌面会话使用官方队列。DSH 原有发送入口的语义不在本次变更范围内。

修正后的专用可见会话：`aaf6aac6-d89d-4bf7-871e-e1b383dfc1ad`。目录为已有专用测试目录 `/private/tmp/relay-visible-claude-20261119`。用户确认看到了 `VISIBLE_CLAUDE_READY`，同时 Adapter 读到真实回复及终端持有状态，channel 完成登记。


测试使用临时 HTTP 端口、临时数据库和随机测试凭证，通过启动进程环境传递测试端口与 token 文件路径；不修改全局 MCP 配置。测试服务的凭证格式和长轮询清理问题修正后，使用 `--resume-launch <本次 launch.json>` 继续同一已打开会话，未重开窗口，未重复首条任务。

请求 `4f2613fb-cddc-4da2-ac85-14316f90b961` 通过 `claude-notify/send.mjs` 进入 channel，收到 ack 摘要 `VISIBLE_CLAUDE_RELAY_f1ebeb1e-17ce-46fd-9e13-a8bd59c474b4`。测试服务重开后，沿用持久化的同一请求核对，仍返回已有消息且不重复投递。实际会话 cwd 与指定目录一致，订阅数量为 0。最终脚本通过并正常退出，测试 HTTP 服务停止；Claude 终端保持可见。

电脑控制工具禁止读取/操作 Terminal 与 Codex 原生界面，本次未绕过该限制。信任与 channel 提示由用户处理；结果通过专用会话记录、桌面原生工具和 channel ack 核对。
