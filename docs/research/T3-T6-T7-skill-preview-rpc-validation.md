# T3、T6、T7 Skill 安装预览 RPC 修复验收

## 问题与根因

2026-11-15，Windows 日常 DSH 的 Codex「前置安装接入」同时显示「通知 Skill：正常」与「不支持的 Relay 操作」。实际加载版本为 `0.1.3`。

`install_skill_preview` 和 `install_skill` 已对外注册，但服务分发缺少对应处理分支，落入不支持操作的默认错误。页面又在安装正常时无条件请求预览，所以安装检查成功仍显示该错误。此错误不代表共享凭证失效或 Codex daemon 连接失败。

## 修复

- 补齐两个 Skill RPC 的服务分发。
- 先检查安装状态，仅在 Codex 尚未正常安装时请求并展示安装提示词；重新检查状态时同步更新预览。
- 增加服务分发、全部已注册操作覆盖，以及正常安装和缺失安装两种页面状态的回归测试。
- 版本更新为 `0.1.4`。未改变凭证，不需要重新生成凭证或安装已有 Skill。

## 真实宿主验收

环境：Windows、Node.js v24.16.0、DSH 0.2.2-rc.1，用户日常 `~/.dsh/profiles/web`。

安装前备份配置与 Relay 数据到 `~/.dsh/backups/agent-relay-skill-rpc-20261115-191829/`。通过 DSH 插件安装命令升级到 `0.1.4`，重启原 web profile；核对已安装包版本为 `0.1.4`。

在原已登录的浏览器刷新，进入「任务跟踪 → 前置安装接入 → Codex」，实际显示：

- 「已安装，无需重复操作」。
- 「通知 Skill：正常 · 通知 Skill 已安装」。
- 「检查安装状态」按钮可用。
- 原红色「不支持的 Relay 操作」消失，正常状态没有多余安装提示词。

本轮未卸载日常 Skill 制造缺失状态；缺失状态的预览与安装 RPC 由临时目录和注入服务测试覆盖。macOS 真实宿主未重跑，本轮改动使用共用服务与前端分支。
